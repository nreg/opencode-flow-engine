> 本文档总结 OpenCode 的**模型参数集**——采样参数在三个配置层面的分布、各自的实际消费点，以及 opencode-flow-engine 将其外置到用户配置的可行性与改造路径。

## 〇、结论速查

| 问题 | 结论 |
|------|------|
| agent 级采样参数有哪些？ | **仅 `temperature` + `top_p`**（OpenCode core agent schema 与 SDK 双套类型一致） |
| `top_k` 在 agent 级支持吗？ | **不支持**。写进 agent 配置会被 schema 静默归并进 `options` 死字典，无任何消费点 |
| `top_k` 运行时支持吗？ | **支持**。属于 AI 运行时层 `GenerationOptions`（8 参数），但注入点在 **provider/model options**，不在 agent 配置 |
| variant 是 agent 级字段吗？ | **是**（core schema 显式声明）；flow-engine 已接线（`agents.<name>.variant` 注册期透传，2026-10-12），生效受五连校验约束（§6.3 / §6.4） |
| flow-engine 可外置的参数全集？ | agent 级 `temperature` / `top_p` / `variant` **均已支持**（2026-10-12；variant 走方案 A 注册期透传）；档位级 `temperature`/`top_p` 已支持（**仅注册期生效**）；扩展采样参数（top_k 等）应在 provider 层配置，不建议外置到 flow-engine |

## 一、三层参数架构总览

模型采样参数在 OpenCode 中分三个层面，逐层收窄：

```text
┌─ 第一层 Agent 配置面（opencode.json agent 节 / 插件注册 cfg.agent[name]）
│    显式采样参数：temperature、top_p —— 仅此两个
│    其余字段：model / variant / prompt / tools / permission / steps / ...
│    未知字段 → 静默归并进 agent.options（自由字典，无消费保证）
│         │
│         ▼
┌─ 第二层 AI 运行时（GenerationOptions，真正到 wire 的参数全集）
│    maxTokens, temperature, topP, topK, frequencyPenalty,
│    presencePenalty, seed, stop
│    来源：LanguageModelDefaults（provider/model 层设定），非 agent 配置
│         │
│         ▼
┌─ 第三层 Provider 配置面（opencode.json provider.models.<model>.options）
     自由字典 { [key: string]: unknown }，随请求透传给 provider SDK
     top_k / frequency_penalty / presence_penalty / seed / max_tokens / stop
     的用户配置入口在这里
```

**核心认知**：`temperature` / `top_p` 是唯二「agent 级一等公民」采样参数；`top_k` 等扩展参数属于运行时层能力，但配置入口在 provider 层。

### 2.2 未知字段归并行为（重要陷阱）

`AgentSchema` 使用 `Schema.StructWithRest`（`agent.ts:40-41`），normalize 阶段（`agent.ts:45-49`）将所有不在 `KNOWN_KEYS` 中的字段**静默归并进 `options`**：

```typescript
const KNOWN_KEYS = new Set(["name", ...Object.keys(AgentSchema.schema.fields)])
const normalize = (agent) => {
  const options = { ...agent.options }
  for (const [key, value] of Object.entries(agent)) {
    if (!KNOWN_KEYS.has(key)) options[key] = value   // 未知字段 → options
  }
  ...
}
```

**后果**：在 agent 配置中写 `top_k`、`frequency_penalty` 等不会报错，但值只会躺在 `agent.options` 里——本次核查未在 core 中定位到「agent.options → 请求参数」的消费点，应视为无效果。

## 六、opencode-flow-engine 外置现状与改造路径

### 6.1 现状（2026-10-12 已接线）

配置 schema `AgentConfigEntry`（`packages/plugin-infra/src/agents/config-loader.ts:11-18`）接受 6 个字段：

```typescript
export interface AgentConfigEntry {
  model?: string;
  temperature?: number;      // ✅ 已接线
  top_p?: number;            // ✅ 已接线（与 temperature 同构，含 top_p=0 边界锚）
  variant?: string;          // ✅ 已接线（方案 A 注册期透传）
  fallbackModels?: string[];
  fallback_models?: string[];
}
```

`agentOverridesFromConfig`（`config-loader.ts:275-310`，映射在 L293-298）以 `!== undefined` 守卫拷贝 `model` / `temperature` / `top_p` / `variant` / `fallback_models`；插件工厂注册 agent 时逐字段构建 `cfg.agent[name]`（`sflow-plugin-factory.ts:648-665`，`combined-plugin-factory.ts:354-371`，`iflow-plugin-factory.ts:330-347` 专属循环 / `382-397` 共享循环），透传 `override?.temperature` / `override?.top_p` / `override?.variant`。

### 6.2 各参数外置可行性

|------|------|---------|

### 6.3 variant 外置的关键语义坑（方案 A/B 均受影响）

依据 variant 机制专项调研（opencode-provider-manager 文档 §1.4），agent.variant 生效需**五连校验**，其中要求「请求模型 == agent 配置的 model」（providerID/modelID 都匹配）。而 flow-engine 的 `call_flow_agent` 每次调用都动态解析模型（`model_type` 路由 / 档位解析 / fallback），注入模型可能 ≠ agent 注册时的模型（`AGENT_MODEL_MAP`）：

- 只有解析结果恰好等于注册模型时（典型：per-agent `agents.<name>.model` 直配且未触发 fallback），variant 才生效
- 走档位路由或降级时 variant **静默回落默认，不报错**
- 若实施方案 B（调用期传 variant），需顺带修复 `normalizeFallbackList` 丢弃 variant 的问题，使换模型时能携带变体
- 运行时消费证据链（schema 声明 / 五连校验代码 / 端到端先例 / SDK 类型）见 §6.4

### 6.4 variant 运行时消费证据链（2026-10-12 补，Gate-3 P1-① 闭环）

`agents.<name>.variant` 经方案 A（注册期透传至 `cfg.agent[name].variant`）落地后，由 OpenCode 侧原生消费。证据链四环（行号均已核实）：

1. **配置面 schema 显式声明**：OpenCode core agent schema `source/opencode/packages/core/src/v1/config/agent.ts:15-17`（即 §七 源码根下的 `packages/core/src/v1/config/agent.ts`）：

   ```ts
   variant: Schema.optional(Schema.String).annotate({
     description: "Default model variant for this agent (applies only when using the agent's configured model)."
   })
   ```

   同 schema L19 亦显式声明 `top_p: Schema.optional(Schema.Finite)`——variant 与 top_p 均是一等配置字段，**不走** §2.2 的"未知字段归并 options"路径。

2. **运行时消费（五连校验）**：`getConfiguredAgentVariant`（`source/opencode/packages/app/src/providers/models/variant.ts:22-34`）——agent.variant 生效需同时满足：① agent 配置了 variant；② agent 配置了 model；③ 所选模型带 variants 名单；④ providerID 匹配；⑤ modelID 匹配。任一不满足即返回 undefined（静默回落，不报错）。配套 `resolveModelVariant`（同文件 L36-41）从 `selected ?? preferred ?? configured` 取值，且要求值在该模型的 variants 名单内（`"default"` 视为未选）。

3. **端到端验证先例**：opencode-provider-manager 项目的 variant 动态下拉（选中即写入 `opencode.json` 的 agent 节）已验证「agent.variant → OpenCode 运行时消费」全链路（含派生名单、三态语义与 33 个测试用例），实现说明见 `E:\work\nreg\opencode-provider-manager\docs\variant变体机制与动态下拉实现.md`（§1.4 运行时消费 / §2 动态下拉实现 / §2.4 测试坐标）。

4. **SDK 类型说明**：v1 SDK `AgentConfig`（`dist/gen/types.gen.d.ts:835-877`）未显式声明 variant，经索引签名（L866-876）透传；v2 SDK `AgentConfig`（`dist/v2/gen/types.gen.d.ts:1351-1379`）在 L1353 显式声明 `variant?: string`。flow-engine 的插件注册走 OpenCode **配置面**（`cfg.agent[name].variant`），由 core schema 消费，不受 SDK 调用面类型约束。

**语义限制（与 §6.3 一致，保留）**：五连校验要求「请求模型 == agent 注册模型」；`call_flow_agent` 每次调用动态解析模型（`model_type` 路由 / 档位解析 / fallback），注入模型可能 ≠ 注册模型 → variant 静默回落默认，不报错。

## 八、常见问题排查

| 现象 | 原因 | 处置 |
|------|------|------|
| agent 配置里写了 `top_k` 无效果 | Schema.StructWithRest 将未知字段归并进 `agent.options`，无消费点 | 移到 provider model options 配置 |
| `agents.<name>.top_p` 配置不生效 | 已接线（2026-10-12）；按四级优先级链排查：程序化 override > `agents.<name>.top_p` > 档位 top_p > 工厂默认 | 见 `agent-builder.ts:637,648-650` 解析链 |
| `agents.<name>.variant` 配置不生效 | 已外置（方案 A 注册期透传）；五连校验要求请求模型 == agent 注册模型 | 按 §6.3 核查模型解析结果（`model_type` 路由 / fallback 会改变注入模型 → 静默回落） |
| `modelProfiles.<tier>.top_p` 不生效 | 档位级采样**仅注册期生效**；或该 agent 未静态绑定此档位 | 确认 `AGENT_PROFILES` 绑定（`agent-builder.ts:105-136`）；SDK 调用面无 per-call 采样参数，属预期 |
| variant 配置后部分调用生效、部分不生效 | 五连校验要求请求模型 == agent 注册模型；`model_type` 路由 / fallback 会改变注入模型 | 预期行为（静默回落默认）；需按调用路径核查模型解析结果 |
| 配置了 `temperature` 但子代理仍用默认温度 | 检查优先级：程序化 override > `agents.<name>.temperature` > 档位 temperature > 工厂默认 | 见 `agent-builder.ts:635` 解析链 |
