# 智能体配置模型体系 v1.1.0

> 本文档为 v1.1.0 版（对应模型档位体系重构 + per-call 动态路由 L1-B）。
> 变更摘要：
> - 档位从 4 档（mechanical/standard/strong/review）扩展为 **6 档**（free/quick/standard/deep/ultra/review）
> - `modelProfiles` 配置结构从 string 格式升级为 **对象格式** `{ model, fallback_models }`（**breaking change，无向后兼容**）
> - `call_flow_agent` 新增可选 **`model_type`** 参数，支持 per-call 动态档位路由
> - 新增内置默认档位映射 **`DEFAULT_PROFILE_MODELS`**
> - 主智能体（sFlow/iFlow）**绕过档位解析**，仅走 `agents` 配置

## 三层架构

智能体配置模型由三层组成：类型契约 → 工厂定义 → 构建/解析引擎，外加一套级联配置覆盖机制。

```text
┌─ 配置层  config-loader.ts      用户级 + 项目级 JSON 配置 → AgentOverrides + ModelProfileConfig(6档)
├─ 构建层  agent-builder.ts      AGENT_REGISTRY + 模型解析链 + DEFAULT_PROFILE_MODELS + AGENT_PROFILES(6档)
├─ 工厂层  workflows/{sflow,iflow,shared}/agents/*.ts   createXxxAgent() 工厂
└─ 类型层  agents/types.ts       AgentFactory / AgentMode / BuiltinAgentName / Overrides
```

## 1. 类型契约（agents/types.ts）

- `AgentFactory`：`(model, options?) => AgentConfig` —— 每个智能体本质是一个返回 `@opencode-ai/sdk` 的 `AgentConfig` 的纯工厂函数
- `AgentMode`：`'primary' | 'subagent' | 'all'`，决定 UI 中模型的选中行为
- `BuiltinAgentName`：24 个内置智能体的联合类型，分四组——SFlow 工作流（11 个）、IFlow 工作流（6 个）、共享横向智能体（test-engineer/review-engineer）、横向命令（flow-intel 等 5 个）
- `AgentOverrideConfig`：`Partial<AgentConfig>` + category/prompt_append/skills/tools/variant/fallback_models，是用户可覆盖的最小单元

## 2. 工厂定义（workflows/*/agents/*.ts）

以 `contract-builder.ts` 为例：`createContractBuilderAgent = (model, options) => ({ id, name, model, instructions, tools })`。每个智能体的系统提示词（instructions）内嵌在工厂里，通过 `getAgentTools()` 拉取工具集。注意：mode 不挂在工厂函数上，而是统一放在构建层的 `AGENT_MODES` 注册表中。

## 3. 构建引擎（agent-builder.ts）—— 核心

五个注册表 + 一个解析函数：

| 注册表 | 作用 |
|--------|------|
| `AGENT_MODES` | 智能体名 → primary/subagent 显式映射（sFlow、iFlow 是 primary，其余 subagent） |
| `AGENT_REGISTRY` | 智能体名 → 工厂函数（来自三个 workflow 目录的 re-export） |
| `DEFAULT_MODELS` | 每个智能体的默认模型（国产模型 `provider/glm-5.1` 等） |
| `AGENT_PROFILES` | 智能体 → **6 档**映射（free/quick/standard/deep/ultra/review），供静态绑定与档位解析 |
| `DEFAULT_PROFILE_MODELS` | **档位 → 内置默认模型** `{ model, fallback_models }`，档位未配置时兜底 |

### 3.1 六档档位体系

| 档位 | 语义 | 推荐特征 | 静态 Agent 绑定 |
|------|------|---------|----------------|
| `free` | 单行修复/零散小改 | 免费模型、小上下文 | **无**（动态路由目标） |
| `quick` | 机械性执行任务 | 高并发、指令遵循高、上下文 200-256K | `release-archivist` |
| `standard` | 通用编排/探索 | 中并发、代码能力强、上下文 200-256K | `need-explorer`, `ui-director`, `spec-merger`, `flow-intel`, `flow-evolve` |
| `deep` | 最强代码能力 | 中并发、代码最强、上下文 200-256K | `spec-writer`, `contract-builder`, `build-executor`, `bug-investigator`, `ui-implementer`, `flow-architect`, `flow-restyle` |
| `ultra` | 复杂波次/长上下文 | 中并发、上下文 512K-1M | **无**（动态路由目标 + 波次密集任务显式路由） |
| `review` | 审查专用（角色档） | 审查能力优先 | `code-reviewer`, `test-engineer`, `review-engineer`, `flow-health` |

- `free` / `ultra` 无静态绑定，是动态路由目标——通过 `call_flow_agent` 的 `model_type` 参数显式选择
- 主智能体 `sFlow` / `iFlow` **不在** `AGENT_PROFILES` 中，绕过档位解析
- 移除 legacy 档位名 `mechanical` / `strong`（TypeScript 类型层强制）

### 3.2 模型解析链（resolveModelWithFallback）

模型解析链（带 provenance 追踪）：

```text
程序化 override > model 参数 > model_type(档位信号) > 配置模型(per-agent, 跳过档位) > AGENT_PROFILES档位解析 > fallback 链 > 系统默认
```

详细优先级（从高到低）：

| 优先级 | 来源 | 说明 |
|--------|------|------|
| 1 | `overrides[name].model` | 程序化 override，provenance `override` |
| 2 | `model` 参数 | 调用时传入，provenance `override` |
| 3 | **`model_type` 显式传入** | 最高档位信号，直接按该档位解析模型 |
| 4 | `agents[name].model` | per-agent 配置覆盖，**跳过档位解析直接使用**；不可用时先试 per-agent fallbacks |
| 5 | `AGENT_PROFILES[name]` → `modelProfiles.<tier>.model` | 用户配置的档位默认（仅 sflow 工作流） |
| 6 | `DEFAULT_PROFILE_MODELS.<tier>.model` | 内置档位默认 |
| 7 | fallback 链 | 见下 |
| 8 | `DEFAULT_MODELS[name]` | 系统默认 |

### 3.3 Fallback 链（按优先级取第一个非空链）

```text
agents[name].fallback_models (per-agent)
  → modelProfiles.<tier>.fallback_models (用户档位配置)
  → DEFAULT_PROFILE_MODELS.<tier>.fallback_models (内置档位默认)
  → DEFAULT_FALLBACKS[name] (legacy agent 级)
```

- 空列表跳过，继续下一非空源
- 首个可用模型（`isModelAvailable`）被选中，provenance `provider-fallback`
- 全部不可用才回退 `DEFAULT_MODELS[name]`

### 3.4 运行时故障转移

运行时可通过 `markModelUnavailable()` 将故障模型加入黑名单，解析时自动跳过。配置有 30 秒缓存（`clearConfigCache()` 可手动失效）。

## 4. 级联配置（config-loader.ts）

- 用户级：`~/.config/opencode/opencode-flow-engine.json`（基础层）
- 项目级：`.flow-engine/sflow/config.json`（覆盖层）
- `loadCascadedSFlowConfig()` 用 `deepMerge` 合并两级；`agentOverridesFromConfig()` 做大小写不敏感匹配，产出 `AgentOverrides`
- `generateConfigTemplate()` 生成含全部智能体的完整配置模板

### 4.1 ModelProfileConfig（v1.1.0 新结构，breaking change）

```typescript
export interface ModelProfileConfig {
  free?: { model: string; fallback_models: string[] };
  quick?: { model: string; fallback_models: string[] };
  standard?: { model: string; fallback_models: string[] };
  deep?: { model: string; fallback_models: string[] };
  ultra?: { model: string; fallback_models: string[] };
  review?: { model: string; fallback_models: string[] };
}
```

- **旧格式（`"standard": "glm-5.1"` string）不再支持**，读取到 legacy 档位名时输出警告并回退 `DEFAULT_PROFILE_MODELS`
- 边界：档位未配置 → 查 `DEFAULT_PROFILE_MODELS`；档位 `model` 为空字符串 → 视为未配置继续 fallback

### 4.2 DEFAULT_PROFILE_MODELS（config-loader.ts 导出常量）

```typescript
export const DEFAULT_PROFILE_MODELS: Record<ProfileTier, { model: string; fallback_models: string[] }> = {
  free:      { model: 'provider/xxx-free',  fallback_models: [] },
  quick:     { model: 'provider/yyy',       fallback_models: [] },
  standard:  { model: 'provider/zzz',       fallback_models: [] },
  deep:      { model: 'provider/glm-5.1',   fallback_models: [] },
  ultra:     { model: 'provider/1m-ctx',    fallback_models: [] },
  review:    { model: 'provider/yyy',       fallback_models: [] },
};
```

## 5. Per-Call 动态路由（call_flow_agent）

`call_flow_agent` 工具新增**可选 `model_type` 参数**（free/quick/standard/deep/ultra/review）：

```text
call_flow_agent.execute(prompt, subagent_type, model_type?)
    │
    ├─ model_type 已传 → 直接作为最高档位信号解析模型
    ├─ model_type 未传 → 查 AGENT_PROFILES[subagent_type] 静态绑定档位
    ├─ 模型解析 → resolveModelWithFallback（完整优先级链 + fallback 链）
    │             + provider/glm-5.1 → { providerID, modelID } 拆分
    └─ session.prompt({ body: { agent, parts, model: { providerID, modelID } } })
           ← @opencode-ai/sdk v1 官方字段，类型安全
```

- **sync / async 模式**均支持 model_type 路由（async 模式在 BackgroundTaskEntry 记录 resolvedModel）
- **无效 model_type** 返回 `formatToolError` 并列出有效档位
- 复杂度评估器（prompt 启发式）**已取消**——档位选择完全由 sFlow 主智能体按 `<Model_Tier_Rules>` 指南自行判断

## 6. 档位决策指南（sFlow 提示词注入）

`sFlow` 的 instructions 末尾新增 `<Model_Tier_Rules>` 块：

| 场景 | model_type |
|------|-----------|
| 单行/零散小改 | free |
| 机械性执行（归档/格式化）或 explore 探索 | quick |
| 常规子任务 | standard |
| 代码执行 | deep |
| 波次任务依赖紧密且任务数量多、需长上下文 | ultra |
| 审查类 | review |

## 7. 插件入口（sflow-plugin-factory.ts）

config hook 阶段调用 `createAllAgents()` 生成全部 `AgentConfig`，写入 `AGENT_MODEL_MAP`，随后以 `PluginModule.agents` 形式注册进 OpenCode，供 `call_flow_agent` / task 工具按名调用。

**一句话总结：** 智能体 = 工厂函数（提示词）+ 注册表（mode/档位/模型/profile）+ 级联配置（可覆盖），三者通过 `createAgent(name)` 统一装配；档位从 4 档扩展为 6 档，`call_flow_agent` 通过可选 `model_type` 实现 per-call 动态路由，模型选择由"默认值 → 配置 → 档位 → fallback"的解析链决定并全程记录 provenance，便于排查模型选型问题。
