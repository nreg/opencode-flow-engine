# 智能体配置模型体系

> **本文档定位：配置结构视角**——三层架构、类型契约、级联配置、配置文件结构。
> **运行时机制视角**（模型如何被选择、降级、换模型）见 `docs/模型路由体系.md`；两文档重复的机制段落已于 2026-10-11 压缩为交叉引用，机制内容以路由体系文档为单一来源。
> **⚠️ 本文档源自 v1.1.0 设计文档，正文保留当时设计原貌。**
> **v1.1.1 已移除全部内置默认模型链**（`DEFAULT_MODELS` / `DEFAULT_FALLBACKS` / `DEFAULT_PROFILE_MODELS` 及 `generateConfigTemplate()` 均已从运行时删除）。
> 涉及这些符号的段落已在原位标注（`> ⚠️ v1.1.1：`），完整说明见文末 **[v1.1.1 变更记录](#8-v111-变更记录)**。**现行行为以该记录为准。**

> 本文档源自 v1.1.0 版（对应模型档位体系重构 + per-call 动态路由 L1-B）。
> 变更摘要：
> - 档位从 4 档（mechanical/standard/strong/review）扩展为 **6 档**（lite/quick/standard/deep/ultra/review）
> - `modelProfiles` 配置结构从 string 格式升级为 **对象格式** `{ model, fallback_models }`（**breaking change，无向后兼容**）
> - `call_flow_agent` 新增可选 **`model_type`** 参数，支持 per-call 动态档位路由
> - 新增内置默认档位映射 **`DEFAULT_PROFILE_MODELS`**（**v1.1.1 已移除**）
> - 主智能体（sFlow/iFlow）**绕过档位解析**，仅走 `agents` 配置

## 三层架构

智能体配置模型由三层组成：类型契约 → 工厂定义 → 构建/解析引擎，外加一套级联配置覆盖机制。

```text
┌─ 配置层  config-loader.ts      用户级 + 项目级 JSON 配置 → AgentOverrides + ModelProfileConfig(6档)
├─ 构建层  agent-builder.ts      AGENT_REGISTRY + 模型解析链 + AGENT_PROFILES(6档)
├─ 工厂层  workflows/{sflow,iflow,shared}/agents/*.ts   createXxxAgent() 工厂
└─ 类型层  agents/types.ts       AgentFactory / AgentMode / BuiltinAgentName / Overrides
```

## 1. 类型契约（agents/types.ts）

- `AgentFactory`：`(model, options?) => AgentConfig` —— 每个智能体本质是一个返回 `@opencode-ai/sdk` 的 `AgentConfig` 的纯工厂函数
- `AgentMode`：`'primary' | 'subagent' | 'all'`，决定 UI 中模型的选中行为
- `BuiltinAgentName`：24 个内置智能体的联合类型，分四组——SFlow 工作流（11 个）、IFlow 工作流（6 个）、共享横向智能体（test-engineer/review-engineer）、横向命令（flow-intel 等 5 个）
- `AgentOverrideConfig`：`Partial<AgentConfig>` + category/prompt_append/skills/tools/variant/fallback_models，是用户可覆盖的最小单元

## 2. 工厂定义（workflows/*/agents/*.ts）

以 `contract-builder.ts` 为例：`createContractBuilderAgent = (model, options) => ({ id, name, model, instructions, tools })`。每个智能体的系统提示词（instructions）内嵌在工厂里，通过 `getAgentTools()` 拉取工具集。注意：mode 不挂在工厂函数上，而是统一放在构建层的 `AGENT_MODES` 注册表中。

## 3. 构建引擎（agent-builder.ts）—— 核心

五个注册表 + 一个解析函数：

| 注册表 | 作用 |
|--------|------|
| `AGENT_MODES` | 智能体名 → primary/subagent 显式映射（sFlow、iFlow 是 primary，其余 subagent） |
| `AGENT_REGISTRY` | 智能体名 → 工厂函数（来自三个 workflow 目录的 re-export） |
| `AGENT_PROFILES` | 智能体 → **6 档**映射（lite/quick/standard/deep/ultra/review），供静态绑定与档位解析 |

> ⚠️ **v1.1.1 已移除**：`DEFAULT_MODELS`（每智能体内置默认模型）与 `DEFAULT_PROFILE_MODELS`（档位内置默认）两个注册表**已删除**。模型现在**只从用户配置**（`modelProfiles.<tier>` 与 `agents.<name>`）解析，未命中任何用户配置时解析结果为 `provenance: 'unconfigured'`（`model: undefined`），由 OpenCode 使用其默认模型。

### 3.1 六档档位体系

档位定义、语义、静态 Agent 绑定明细与关键规则见 **《模型路由体系.md》§二**（单一来源，此处不再重复）。

配置视角要点：

- 档位集合为闭集（`VALID_MODEL_TIERS`，`agent-builder.ts:18`）；legacy 4 档名 `mechanical` / `strong` 已在 TypeScript 类型层强制移除
- 读取到 legacy 档位名或 string 格式时输出警告并忽略（边界行为见 §4.1）

### 3.2 模型解析链（resolveModelWithFallback）

解析链一览（7 级优先级明细、per-tier/per-agent 行为与 provenance 追踪见 **《模型路由体系.md》§三**，单一来源）：

```text
程序化 override > model 参数 > model_type(档位信号) > 配置模型(per-agent, 跳过档位) > AGENT_PROFILES档位解析 > fallback 链 > unconfigured(不注入模型)
```

> ⚠️ **v1.1.1**：链尾原为「系统默认 `DEFAULT_MODELS[name]`」，现已改为 `unconfigured`——不使用任何内置默认模型。

### 3.3 Fallback 链（按优先级取第一个非空链）

取链顺序、空链跳过、黑名单交互与链尾行为见 **《模型路由体系.md》§四**（单一来源）。链结构：

```text
agents[name].fallback_models (per-agent)
  → modelProfiles.<tier>.fallback_models (用户档位配置)
```

> ⚠️ **v1.1.1 移除项**：原链尾的 `DEFAULT_PROFILE_MODELS.<tier>.fallback_models`（内置档位默认）与 `DEFAULT_FALLBACKS[name]`（legacy agent 级）已删除，fallback 链现在**完全来自用户配置**。

### 3.4 运行时故障转移

黑名单 TTL 语义、换模型链路与三重终止条件见 **《模型路由体系.md》§六**（单一来源）。配置有 30 秒缓存（`clearConfigCache()` 可手动失效）。

## 4. 级联配置（config-loader.ts）

- 用户级：`~/.config/opencode/opencode-flow-engine.json`（基础层）
- 项目级：`.flow-engine/sflow/config.json`（覆盖层）
- `loadCascadedSFlowConfig()` 用 `deepMerge` 合并两级；`agentOverridesFromConfig()` 做大小写不敏感匹配，产出 `AgentOverrides`

> ⚠️ **v1.1.1 已移除**：`generateConfigTemplate()` 函数已**删除**（原用于生成含全部智能体的完整配置模板，模板内的占位模型会产生"内置默认"认知）。配置模板能力现由 `bin/flow-engine.js` 的 `TEMPLATE_PLACEHOLDER_MODELS` 常量提供 `your-provider/*` 占位符，**不含任何真实/默认模型值**。

### 4.1 ModelProfileConfig / ModelProfileTierConfig（v1.1.0 新结构 + 采样参数扩展）

```typescript
export interface ModelProfileTierConfig {
  model: string;              // 必填（不变）
  fallback_models: string[];  // 必填（不变）
  temperature?: number;       // 可选：档位级采样温度
  top_p?: number;             // 可选：档位级采样 top_p
}

export interface ModelProfileConfig {
  lite?: ModelProfileTierConfig;
  quick?: ModelProfileTierConfig;
  standard?: ModelProfileTierConfig;
  deep?: ModelProfileTierConfig;
  ultra?: ModelProfileTierConfig;
  review?: ModelProfileTierConfig;
}
```

（现行代码：`packages/plugin-infra/src/agents/config-loader.ts:27-41`——六档统一引用 `ModelProfileTierConfig`。）

- **旧格式（`"standard": "glm-5.1"` string）不再支持**，读取到 legacy 档位名时输出警告并忽略该档位
- 边界：档位未配置 → 继续下一优先级（原为查 `DEFAULT_PROFILE_MODELS`）；档位 `model` 为空字符串 → 视为未配置继续 fallback
- **档位级采样参数（`temperature` / `top_p`，2026-10-12 扩展）**：可选字段；按 `AGENT_PROFILES` 静态绑定档位在 `createAgent` 内部解析（`agent-builder.ts:632-650`），四级优先级链第 3 级（程序化 override > `agents.<name>` per-agent > 档位 > 工厂默认），temperature 与 top_p **独立走链**；`createAllAgents` 镜像同一逻辑（`agent-builder.ts:704-713`）。**仅注册期生效**——v1/v2 SDK 调用面无 per-call 采样参数，`model_type` 动态路由只换模型、不换采样。sFlow/iFlow 主智能体不在 `AGENT_PROFILES`，豁免档位级采样

### 4.2 ~~DEFAULT_PROFILE_MODELS~~（v1.1.1 已移除）

> ⚠️ **v1.1.1 变更**：本节描述的常量 `DEFAULT_PROFILE_MODELS: Record<ProfileTier, { model, fallback_models }>` **已从运行时删除**。
> 它曾是"档位 → 内置默认模型"的兜底映射（如下方已废弃示例），导致用户未配置时仍会调用内置模型——这与"模型解析只遵循用户配置"的目标冲突。
> 现行行为：**档位未配置即不解析出模型**（`unconfigured`）。需要默认模型时请在用户配置 `modelProfiles.<tier>` 中显式声明。

```typescript
// ❌ 已删除（v1.1.1），仅作历史参考
export const DEFAULT_PROFILE_MODELS: Record<ProfileTier, { model: string; fallback_models: string[] }> = {
  lite:      { model: 'provider/xxx-lite', fallback_models: [] },
  quick:     { model: 'provider/yyy',       fallback_models: [] },
  standard:  { model: 'provider/zzz',       fallback_models: [] },
  deep:      { model: 'provider/glm-5.1',   fallback_models: [] },
  ultra:     { model: 'provider/1m-ctx',    fallback_models: [] },
  review:    { model: 'provider/yyy',       fallback_models: [] },
};
```

### 4.3 共享智能体 per-agent 配置（FU-1，2026-10-12 扩展）

`BUILTIN_AGENTS` 白名单（`config-loader.ts:254-278`）已从 15 个扩展为 22 个，追加 7 个共享智能体名（来源：`workflows/shared/index.ts` 的 `SHARED_AGENT_NAMES`）：

`test-engineer`、`review-engineer`、`flow-architect`、`flow-intel`、`flow-evolve`、`flow-health`、`flow-restyle`

因此 `agents.<name>` per-agent 配置对这 7 个共享智能体**可达**，优先级与工作流子代理一致：

- `agentOverridesFromConfig()`（受 `BUILTIN_AGENTS` 白名单门控）为共享智能体生成 per-agent override
- F4 共享注册循环（`iflow-plugin-factory.ts:361-402`）经 `override?.temperature/top_p/variant` 透传；`model`/`fallback_models` 经 `createAgent` Priority 4 config-override（跳过档位解析）与 fallback 链生效
- 字段级合并：per-agent 字段覆盖 `AGENT_PROFILES` 静态绑定档位的同名字段，未配置字段从档位继承
- 白名单扩展后三个工厂共享循环零源码改动自动透传（钉死用例：`plugin-factory-sampling.test.ts` SP-17）

## 5. Per-Call 动态路由（call_flow_agent）

`call_flow_agent` 工具提供**可选 `model_type` 参数**（lite/quick/standard/deep/ultra/review）；工具层流程、sync/async 支持与无效值处理见 **《模型路由体系.md》§七**（单一来源）。

- 复杂度评估器（prompt 启发式）**已取消**——档位选择完全由 sFlow 主智能体按 `<Model_Tier_Rules>` 指南自行判断

## 6. 档位决策指南（sFlow 提示词注入）

`sFlow` 的 instructions 末尾注入 `<Model_Tier_Rules>` 块；场景 → `model_type` 决策表见 **《模型路由体系.md》§七**（单一来源，此处不再重复）。

## 7. 插件入口（sflow-plugin-factory.ts）

config hook 阶段调用 `createAllAgents()` 生成全部 `AgentConfig`，写入 `AGENT_MODEL_MAP`，随后以 `PluginModule.agents` 形式注册进 OpenCode，供 `call_flow_agent` / task 工具按名调用。

**一句话总结：** 智能体 = 工厂函数（提示词）+ 注册表（mode/档位/profile）+ 级联配置（可覆盖），三者通过 `createAgent(name)` 统一装配；档位从 4 档扩展为 6 档，`call_flow_agent` 通过可选 `model_type` 实现 per-call 动态路由。

> ⚠️ **v1.1.1 更正**：末句原表述「模型选择由『默认值 → 配置 → 档位 → fallback』的解析链决定」已过时。现行解析链**没有"默认值"环节**——只读用户配置（`modelProfiles.<tier>` → per-agent `agents.<name>`），全链未命中则返回 `unconfigured` 不注入模型。provenance 追踪保留，便于排查模型选型问题。

## 8. v1.1.1 变更记录

> 对应变更：**移除内置默认模型链，模型解析只遵循用户配置**。本文 v1.1.0 正文中标注 `⚠️ v1.1.1` 的段落均以本节为准。

### 8.1 动机

v1.1.0 的解析链内置了三层兜底（`DEFAULT_PROFILE_MODELS` / `DEFAULT_FALLBACKS` / `DEFAULT_MODELS`），导致：

1. 用户**未配置任何模型时仍会静默调用硬编码的内置模型**，行为不可预期且与用户意图相悖；
2. 内置模型值随版本漂移，用户难以确认"这个子代理到底在用哪个模型"；
3. 调试成本高——provenance 的 `system-default` 掩盖了"其实就是没配"。

v1.1.1 确立原则：**模型只来自用户配置，没有配置就没有注入**。

### 8.2 删除清单

| 符号 | 原位置 | 原职责 | 处置 |
|------|--------|--------|------|
| `DEFAULT_MODELS` | `agent-builder.ts` | 每智能体内置默认模型 | **已删除** |
| `DEFAULT_FALLBACKS` | `agent-builder.ts` | legacy agent 级内置 fallback | **已删除** |
| `DEFAULT_PROFILE_MODELS` | `config-loader.ts` | 档位 → 内置默认模型 + 内置 fallback | **已删除** |
| `generateConfigTemplate()` | `config-loader.ts` | 生成含占位/默认模型的完整配置模板 | **已删除** |
| `TEMPLATE_PLACEHOLDER_MODELS` | `bin/flow-engine.js` | CLI 配置模板的 `your-provider/*` 占位符 | **保留并集中为常量**（占位符非真实模型，不参与运行时解析） |

### 8.3 新解析链（现行）

```text
1. overrides[name].model              → 'override'
2. model 参数                          → 'override'
3. model_type 显式指定                  → 用户 modelProfiles.<tier>.model → 'profile'
                                         （不可用则走 fallback 链 → 'provider-fallback'）
4. agents[name].model                  → 'config-override'
5. AGENT_PROFILES[name] → 用户档位 model → 'profile'
6. fallback 链：per-agent → 用户档位      → 'provider-fallback'
7. 链尾：无配置                          → { model: undefined, provenance: 'unconfigured' }
```

- **`unconfigured` 语义**：调用方**不向 `session.prompt` 注入 `model` 字段**，由 OpenCode 使用其默认模型。这是预期行为，不是错误。
- **fallback 链仅来自用户配置**：per-agent `fallback_models` + `modelProfiles.<tier>.fallback_models`，不再拼接任何内置列表。
- `getAlternativeModel()`（运行时换模型）同样只遍历用户配置链（`buildAgentFallbackChain`），不再叠加 `DEFAULT_FALLBACKS`。
- `ModelProvenance` 类型：`'system-default'` 已移除，新增 `'unconfigured'`。

### 8.4 迁移指引

用户侧无破坏性改动——**升级后未配置模型的智能体将改用 OpenCode 默认模型**而非原先的内置模型。若希望维持既有模型选择，在用户配置中显式声明即可：

```json
{
  "modelProfiles": {
    "deep": { "model": "provider/your-model", "fallback_models": ["provider/backup"] }
  },
  "agents": {
    "build-executor": { "model": "provider/your-model", "fallback_models": ["provider/backup"] }
  }
}
```

配置模板占位符（`your-provider/*`）需替换为真实模型后才生效，不再是"填了就跑默认模型"。

### 8.5 影响面

- 解析引擎：`agent-builder.ts`（`resolveModelWithFallback` / `buildFallbackChain` / `getAlternativeModel` / `buildAgentFallbackChain`）
- 配置层：`config-loader.ts`（删除 `DEFAULT_PROFILE_MODELS` 与 `generateConfigTemplate`）
- CLI：`bin/flow-engine.js`（占位模板集中为 `TEMPLATE_PLACEHOLDER_MODELS`）
- 全量测试 2278 项通过；`tsc --noEmit` 零错
